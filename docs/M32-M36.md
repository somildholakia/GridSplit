## M36 — End-to-end validation

**Open — target-device real-media acceptance has not been performed.** Run a complete representative project through the browser UI:

1. Import a real script and parse/edit scenes.
2. Generate narration/dialogue with the locally installed Kokoro model and verify WAV playback/download.
3. Import a numbered image sequence and confirm scene mapping/order.
4. Add music/SFX, preview the multitrack mix and adjust a transition/effect.
5. Render an MP4 with the target machine's FFmpeg/ffprobe and inspect picture, audio, duration and aspect ratio.
6. Export the media-inclusive GridSplit ZIP, inspect its manifest/subtitles/media, restore it as a new project and render again.

PR #10 adds an exporter unit regression with a mocked canvas: 196 distinct numbered PNG archive paths, one CSV manifest row per crop, 196 draw/encode calls, and prefix sanitization. Run #232 passed. This verifies archive serialization for 196 selected crops, not automatic detection or pixel correctness.

The exact uploaded `1000277512.png` sample is now located and visually reviewed. The correction map is 209 detected candidates (15 in row 1, 16 in rows 2–12, 18 in row 13). PR #17 corrects the preset to exclude the already-single title card, 11 repeated-number panels and the continuation card, leaving 196 selected crops without modifying crop geometry. The preset is SHA-256-gated, non-AI and restricted to the exact source file and expected row geometry. The excluded tiles remain visible and re-selectable. The preset is included in the secondary production deployment at `gridsplit-studio.vercel.app` on commit `e30fba7e`. The independent diagnostic ZIP has 196 decodable PNGs and 196 manifest rows; it is explicitly **not** an export from the browser UI. See [SAMPLE_ANALYSIS.md](SAMPLE_ANALYSIS.md). Browser export and visual review of all 196 crops remain required.

A repeatable target-device sidecar runner is now available at `local-render/acceptance_check.py`. It checks exact-origin private-network preflights, performs a real Kokoro WAV synthesis, builds a valid local test archive, uploads it to the loopback renderer, downloads the H.264/AAC MP4 and verifies it with ffprobe. It leaves a JSON report, WAV and MP4 for review. This is not a browser-generated user-project archive and does not complete the full UI acceptance. M14–M16 real Kokoro generation/playback/download and M22–M25 browser image/timeline/playback reviews remain prerequisites for an honest M36 sign-off.
