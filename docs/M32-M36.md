## M32 — Integration testing

**Automated slice complete.** The frontend integration test exercises script headings/markers, scene and block parsing, measured sample-based timing, SRT/VTT generation, image-to-scene mapping and production timeline construction. The Python integration test starts the real loopback renderer, uploads a manifest-validated ZIP, polls the render job and downloads an MP4 validated as H.264/AAC.

**Not claimed:** browser automation across all React workflows, live Kokoro inference, or an archive exported by the browser UI from a real user project.

## M33 — Performance optimization

**Regression baseline complete.** CI processes a synthetic 500-scene, 500-image and 1,000-clip project under a 10-second ceiling. Renderer resource limits cap active jobs at two and retained finished jobs at eight/six hours.

**Not claimed:** target hardware benchmarks for actual image decoding, local TTS inference, memory pressure, or long-form/high-resolution rendering.

## M34 — Security and privacy review

**Application-level review recorded.** See [SECURITY_REVIEW.md](SECURITY_REVIEW.md). CI runs a production npm audit and regression checks for loopback Host validation and renderer archive handling. The latest npm audit reported no production vulnerabilities at the high-severity threshold.

**Release gate:** Python package dependencies currently do not have a committed lockfile or CI vulnerability audit. Exact versions/licenses for user-installed Kokoro models, voice files, phonemizer/runtime dependencies, FFmpeg builds and codecs need a separate review before bundling or redistribution.

## M35 — Production deployment

**Open.** The current feature branch has a READY Vercel preview, but the production deployment still tracks `main` (M01–M05 baseline). PR #1 remains a draft and is not merged. Production promotion requires the remaining target-device acceptance and a release decision; hosting only serves the static frontend and does not become a media-processing service.

## M36 — End-to-end validation

**Open.** Run a complete representative project through the browser UI:

1. Import a real script and parse/edit scenes.
2. Generate narration/dialogue with the locally installed Kokoro model and verify the WAV playback/download.
3. Import a numbered image sequence and confirm scene mapping/order.
4. Add music/SFX, preview the multitrack mix and adjust a transition/effect.
5. Render an MP4 with the target machine's FFmpeg/ffprobe and inspect picture, audio, duration and aspect ratio.
6. Export the media-inclusive GridSplit ZIP, inspect its manifest/subtitles/media, restore it as a new project and render again.

The existing HTTP test uses a small deterministic image archive and validates the renderer API; it is not a substitute for this full target-device acceptance. The M14–M16 and M22–M25 manual gates are prerequisites for an honest M36 sign-off.
