# GridSplit Studio — M12–M16 audio workflow

**Implementation scope:** Character management through first playable local speech segments  
**TTS candidate:** Kokoro ONNX via an optional loopback sidecar  
**Data policy:** project metadata in browser-local storage; generated WAV blobs in IndexedDB

## M12 — Character management

- Extract dialogue speakers from parsed script blocks and create stable per-project character records.
- Maintain a dedicated Narrator identity when narration blocks exist.
- Save voice ID, language, and synthesis speed per character; reuse assignments across scenes.
- Allow adding, renaming, editing voice settings, and removing only unused characters.
- A text or voice setting change invalidates only the affected generated segment fingerprint.

## M13 — Offline TTS provider abstraction

- Define engine-independent provider, voice, health, request, and result contracts.
- Results carry actual WAV sample count, sample rate, channels, and duration.
- The provider contract supports AbortSignal cancellation and explicit errors.
- No cloud provider or automatic fallback is included.

## M14 — Local TTS integration

- Provide an optional Python sidecar using `kokoro-onnx==0.6.1`, FastAPI, Uvicorn, and SoundFile.
- The sidecar listens on `127.0.0.1:8765` and exposes `/health`, `/voices`, and `/synthesize`.
- Model and voice files are user-installed; GridSplit does not download or bundle model weights.
- The browser adapter rejects non-loopback hosts. The sidecar CORS allowlist defaults to local development origins; trusted deployed origins can be explicitly configured.
- PyPI currently lists kokoro-onnx 0.6.1, Python >=3.10 and <3.14, MIT package licensing, and Apache-2.0 model licensing. Each voice, phonemizer, runtime and transitive dependency retains its own license and provenance. See the [PyPI setup and license details](https://pypi.org/project/kokoro-onnx/) and [official voice catalog](https://huggingface.co/hexgrad/Kokoro-82M/blob/main/VOICES.md).

## M15 — Segment generation

- Derive stable segment records for narration and dialogue blocks only.
- Fingerprint text, voice, language, and speed. Editing one segment does not reset unrelated ready segments.
- Generate, cancel, retry, and regenerate one speech segment at a time.
- Store generated WAV Blob data in IndexedDB; keep only status and technical metadata in project storage.
- Stale `generating` records are recovered to `pending` after a page reload.

## M16 — Audio preview

- Use the browser's native audio player for local WAV review.
- Display real duration and sample rate derived from the generated WAV header.
- Download an individual generated segment as WAV.
- Regenerate one segment without invalidating successful unrelated segments.

## Validation boundary

The browser workflow is covered by Vitest, lint, typecheck, and production build once CI passes. The optional Python sidecar is not considered runtime-verified until installed with the matching model/voice files and a real synthesis request has been checked on a target machine. No word-level alignment is claimed. M17 handles canonical duration correction, M18 synchronization metadata, and M19 subtitle generation.
