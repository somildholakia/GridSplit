# GridSplit Studio — M26–M31 mixer, rendering and portable projects

**Implementation scope:** M26–M31  
**Execution model:** local browser storage plus an optional loopback renderer  
**New network dependency:** none for project processing

This note records the runtime implementation added after M25. It distinguishes automated validation from the user-device acceptance that still requires an installed FFmpeg build.

## M26 — Audio mixing

- Adds independent narration, dialogue, music and SFX mix tracks.
- Persists per-track volume (0–200%), mute, solo, fade-in and fade-out settings in the project.
- Supports local browser-decodable music/SFX imports, with duration measured by Web Audio and original blobs stored in IndexedDB.
- Mix preview schedules generated local narration/dialogue WAVs and imported music/SFX using Web Audio gain nodes and fade automation.
- A track solo selection takes precedence over other unmuted tracks; muted tracks remain silent.

No audio file is sent to an application server for preview or storage.

## M27 — Transitions and image effects

- Adds per-image-clip transition-in and transition-out settings: cut, fade, dissolve, wipe-left and wipe-right.
- Adds static, Ken Burns, pan-left, pan-right, zoom-in and zoom-out presets.
- Persists the effect settings and bounded zoom/transition parameters on the corresponding timeline clip.
- The optional local FFmpeg renderer interprets these settings when rendering.

The live timeline remains the source of clip order and timing. Effect controls do not silently rewrite clip timing.

## M28 — Local FFmpeg renderer

- Adds an optional Python-standard-library sidecar at local-render/server.py.
- The sidecar binds to 127.0.0.1 only and requires an explicit exact-origin allowlist.
- The browser sends a complete project ZIP to the local process. The sidecar rejects unsafe paths, excessive archive sizes/entry counts, unexpected Host/Origin headers and media checksum mismatches.
- Job status and render progress are queryable; a running FFmpeg process can be cancelled.
- Video gaps are filled with black; images are fitted/cropped to the selected dimensions; configured transitions and motion effects are applied.
- Speech WAVs and imported music/SFX are scheduled from project timeline metadata and mixed with the saved track volume/mute/solo/fade settings.
- FFmpeg and ffprobe are user-installed. No executable, codec binary or model is bundled and no cloud render fallback exists.

Start the sidecar from the repository root:

    python local-render/server.py --allow-origin http://localhost:5173

See local-render/README.md for exact setup, security boundaries and dependency notes. Use the exact frontend origin that appears in the browser address bar. The renderer is not exposed on a LAN interface.

## M29 — MP4 profiles and validation

- Supports landscape 16:9 (1920×1080 or 1280×720), portrait 9:16 (1080×1920), and square 1:1 (1080×1080).
- Supports 24, 25, 30 and 60 FPS in the UI. The domain validator also accepts common fractional broadcast rates.
- Encodes H.264 video with AAC audio using the installed FFmpeg build.
- Runs a preflight check for missing image binaries, empty timelines, unsupported dimensions, odd dimensions and aspect-ratio mismatches.
- Runs ffprobe after rendering and rejects results whose container, codecs, dimensions, frame rate or duration do not match the requested profile.

A successful archive upload or FFmpeg process exit alone is not treated as successful MP4 export. The output must pass ffprobe validation before the browser downloads it.

## M30 — Complete portable ZIP export

The .gridsplit.zip archive contains:

- project.json — editable scenes, script, audio segment metadata, image mappings, timeline, mix settings, effects and render profile.
- media/images/ — original source image bytes.
- media/generated-audio/ — every ready, locally stored speech WAV.
- media/mix-audio/ — imported music and SFX source files.
- metadata/synchronization.json — fresh rational sample-derived timing rebuilt from the saved WAV headers.
- subtitles/subtitles.srt and subtitles/subtitles.vtt — segment-level captions from the same measured timing.
- manifest.json — per-file path, MIME type, size and SHA-256 digest.
- README.md — local restore instructions and archive description.

The export fails clearly when a referenced original image, ready WAV or imported mix asset is missing. It does not silently create an incomplete archive. The archive is generated and downloaded in the browser.

## M31 — Project restoration

- Restore reads the ZIP locally and checks entry count, path safety, project schema, media sizes and SHA-256 checksums before storing imported assets.
- The restored project receives new project, scene, block, image, audio-segment, mix-track and timeline-clip IDs; all internal references are remapped.
- Original image binaries are written to the existing image IndexedDB store. Generated speech WAVs use the existing audio store. Music/SFX use the new project media store.
- A failed restore removes media written by that restore attempt.
- Restore adds a new project and leaves the source project unchanged.
- Music/SFX blobs are intentionally not copied by the ordinary Duplicate Project action; the duplicate retains mix settings but starts with an empty imported music/SFX list. Use the portable archive for a full media-preserving copy.

## Automated validation

The branch CI workflow now installs FFmpeg on the ephemeral Ubuntu runner, compiles both Python sidecars, runs archive-safety/checksum tests, and renders a small test project with a transition and audio mix before the existing npm lint/test/typecheck/build steps. The browser project schema and mix/effect logic also have unit tests.

The CI render is a test fixture, not a validation of every user-installed FFmpeg build or every image/audio format. A real browser acceptance pass with a target-device Kokoro model, representative storyboard and final MP4 remains a manual release check.

## Known limits and release acceptance

- The optional renderer must be started on the same computer as the browser. It is not compatible with a remote processing endpoint.
- The user must install FFmpeg and ffprobe, with libx264 and AAC support. GridSplit does not download or bundle them; codec and distribution licensing depends on the user's exact FFmpeg build and its linked libraries.
- The renderer validates the archive before rendering but cannot guarantee every third-party media file is decodable by every FFmpeg build.
- The app still stores project metadata in localStorage and media binaries in IndexedDB; browser storage quotas remain relevant. Export portable archives regularly.
- The M22–M25 manual browser timeline/playback review and M14–M16 real Kokoro synthesis review remain open.
- M32 end-to-end workflow validation, M33 performance profiling, M34 broader security review, M35 deployment and M36 final package acceptance remain outside this milestone scope.
