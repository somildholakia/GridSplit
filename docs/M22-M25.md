# GridSplit Studio — M22–M25 Image-to-Timeline Workflow

This document records the production workspace implementation added after M21. It distinguishes the live workspace from planned rendering, mixing, and packaging work.

## M22 — Project-local image sequence management

- Imports multiple images or browser-supported folders into the active project.
- Stores original image blobs in IndexedDB and keeps lightweight asset metadata in the project record.
- Builds local thumbnail previews from the stored original blobs.
- Reads frame numbers from the last numeric token in a filename, including nested POSIX and Windows paths.
- Flags missing frame numbers, sequence gaps, repeated frame numbers, and matching content fingerprints.
- Enforces a 500-image project limit and allows manual frame-number correction, visual reordering, individual removal, and clearing the project sequence.
- Duplicate content remains available for human review; no imported image is silently discarded.

Image blobs are shared by stable asset ID when a project is duplicated. Removing an asset or deleting a project only removes an IndexedDB blob when no other saved project references it. A backup that contains image metadata but no local source blob produces a visible re-import warning; failed multi-file imports roll back blobs saved earlier in the same batch.

## M23 — Scene-to-image mapping

- Each scene can map to any number of images.
- The same image can be reused in more than one scene.
- Mapping normalization removes invalid references and duplicate IDs and merges repeated mapping rows for the same scene.
- Mapping order follows the current manual image-sequence order, so reordering assets updates the order used by schedule generation.
- Mapping and image-asset metadata are stored with the project record.
- Project duplication remaps scene references and copies the mapping metadata while retaining shared image blob IDs.

## M24 — Measured automatic synchronization

- Builds an initial two-track schedule (images and scene audio) from current scene order, image mappings, and generated WAV segments.
- Re-reads each saved WAV header using the existing sample-count/sample-rate measurement path instead of trusting estimated TTS duration.
- Distributes each scene's measured duration evenly across its mapped images to create an editable starting schedule.
- Reports scenes with no ready audio, missing/unreadable WAV blobs, or no mapped images.
- Rebuilding is explicit; manual timeline edits are not silently recalculated until the user asks to rebuild.

The live Production Workspace persists start/duration values in seconds in its project-local timeline extension. The separate rational-time timeline helper under src/lib/productionTimeline.ts remains a tested domain utility; it is not yet the live editor's canonical storage format.

## M25 — Visual timeline and synchronized local playback

- Displays proportional image and audio lanes with a time ruler and visible playhead.
- Includes play, pause, stop, and seek controls.
- Shows the image covering the playhead position in a preview monitor.
- Supports clip start/duration editing and half-second position nudges.
- Schedules locally stored narration/dialogue WAV blobs with the audio scene clip positions using the browser Web Audio API.
- Retains individual audio segment players as a fallback review path.

## Validation and acceptance boundaries

Automated coverage includes filename parsing, natural sorting, sequence gap/duplicate review, many-to-many mapping cleanup, measured-duration schedule distribution, image selection at timeline boundaries, timeline movement, project metadata validation, and correct scene/mapping/clip remapping during project duplication. GitHub Actions run #182 passed lint, 76 tests across 15 files, typecheck, production build, optional sidecar syntax check, and artifact upload: https://github.com/somildholakia/GridSplit/actions/runs/42826679257.

A passing CI run validates lint, unit tests, typecheck, production build, sidecar syntax, and artifact upload. It does not replace manual browser testing with a representative image batch and actual model-generated WAV files.

This milestone does not implement audio mixing, music/SFX track processing, transitions, pan/zoom effects, MP4 rendering, or a media-inclusive portable project archive. JSON backup preserves project metadata but does not embed IndexedDB image or audio binaries; complete media packaging is planned for M30.
