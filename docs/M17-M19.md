# GridSplit Studio — M17–M19 timing and subtitle workflow

## M17 — Actual WAV duration measurement

- The export workflow re-opens each generated audio Blob from IndexedDB and reads the RIFF/WAVE header.
- Duration is derived from the actual sample-frame count divided by the WAV sample rate; provider estimates and browser player timing are not used as the source of truth.
- Sample count, sample rate, channel count, and reduced rational duration are retained for the export operation.
- Missing, truncated, unsupported, or invalid WAV blobs are skipped and reported rather than assigned guessed durations.

## M18 — Deterministic synchronization metadata

- Ready narration/dialogue segments are laid out sequentially in their existing scene/block order.
- Segment and scene start/end positions use exact rational seconds, preserving sample-derived timing across differing sample rates.
- Exported JSON uses schema `gridsplit.sync`, version 1, and records segment references, sample metadata, scene groupings, total duration, and rational start/end/duration values.
- The generated schedule is deterministic for the same ordered segment list and WAV metadata. It is not yet an editable timeline or automatic scene-to-image mapping.

## M19 — SRT/VTT subtitle generation

- Export SRT and WebVTT captions from the same measured segment timing used by the synchronization JSON.
- Captions are one cue per narration/dialogue segment. Dialogue cues include the speaker label.
- Cue text is taken from the source script block; line breaks are normalized.
- No word-level or phoneme-level alignment is claimed. Word timing remains out of scope until an engine provides trustworthy alignment data.

## Validation boundary

Automated coverage checks mixed sample rates, exact rational accumulation, deterministic scene grouping, duplicate/invalid metadata rejection, subtitle timestamp formats, and empty caption handling. A manual target-device Kokoro generation test remains a separate M14–M16 acceptance item.
